# 武汉真实餐厅数据建设说明

## 目标与边界

NightFind 将武汉真实餐厅作为独立数据集维护，与研究演示商户彻底分开。真实记录必须同时满足：

1. 有可追溯的数据来源和来源记录。
2. 来源明确允许夜寻存储、加工和展示相应字段。
3. 记录属于武汉市 13 个行政区之一。
4. 名称、行政区、真实门店地址和来源凭证完整。
5. 经人工核验后，才进入公开 API 和前端真实餐厅目录。

**当前阶段不提供未经授权的地图/点评网站批量抓取器。** 地图 POI、营业时间、菜单、照片、评论和价格分别可能受到平台服务条款、数据库权利、著作权或商家授权限制。公开可浏览不等于允许批量复制、长期存储或商业展示。

## 首批地理范围

系统将行政区与功能区分开记录。首批行政区：

- 江岸区、江汉区、硚口区、汉阳区、武昌区、青山区、洪山区
- 蔡甸区、江夏区、黄陂区、新洲区、东西湖区、汉南区

另设功能区标签：东湖高新区、武汉经开区、临空港经济技术开发区、长江新区、武汉化学工业区、东湖风景区。功能区不是额外行政区，导入时仍须填写实际行政区。

## 数据来源优先级

| 来源 | 使用方式 | 入库条件 |
| --- | --- | --- |
| 商家自主提交/认领 | 商家填写资料并确认授权 | 保存授权记录及提交凭证；人工核验门店 |
| 武汉市公共数据授权运营 | 通过官方授权运营渠道申请数据产品/接口 | 取得对应授权协议、字段范围和展示权限 |
| 合法商业 POI 服务 | 使用地图或商业数据供应商正式 API | 确认存储、缓存、展示、衍生加工及归属标注权限 |
| 人工核验的商家官方信息 | 官方网站/公众号/商家书面资料 | 核对来源条款及可展示范围，记录来源链接和核验日期 |
| 用户到店反馈 | 夜寻用户主动提交 | 与商家基础资料分表保存；审核后展示，不当作官方事实 |

## 数据字段与缺失值

- 必填：餐厅名称、行政区、门店地址、来源凭证和来源资料更新日期（source_updated_at，YYYY-MM-DD）。
- 当前 CSV 导入器支持的可选字段：分店名、商圈、经纬度、电话、官网、菜系、人均价格、营业状态、描述、来源更新时间。
- 数据库已预留营业时间和菜品扩展表；本阶段尚未提供这两类资料的导入/审核命令，因此不会显示未导入或未经核验的营业时间、菜单。
- 未知价格必须为 NULL；未知营业状态为 unknown；未知营业时间保持空，不得推测。
- 不收集顾客个人手机号、身份证号、家庭住址或与商家目录无关的个人信息。
- 不将第三方平台评分/评论直接复制到夜寻；用户评价另行征得提交者同意并进行审核。

## 数据状态

- pending：来源许可有效，但尚未完成门店核验。
- needs_review：系统发现疑似重复或数据冲突，需要人工确认。
- verified：来源许可有效且人工核验通过，可在公开目录展示。
- rejected：审核未通过，不公开。

如果来源许可被暂停，来自该来源的已核验记录也会立即从公开 API 隐藏。

## 更新和质量管理

建议先建立以下运营节奏（这是运营目标，不代表已接入实时数据）：

- 商家基础资料：商家变更通知或定期回访时更新。
- 营业时间、营业状态：本阶段营业状态可随基础门店资料导入；营业时间扩展表已预留，专用导入/审核流程待后续实现。尽可能在每次核验时记录日期；临时状态不得标成实时。
- 价格/菜单：记录来源更新时间；无法确认的价格不展示。
- 每次更新记录来源、批次、操作者和字段变更；疑似重复进入人工复核。
- 对外页面显示最后核验日期，并提示用户到店前再次确认。

## CSV 导入流程

1. 复制 examples/wuhan_restaurants_template.csv 并填写；使用 UTF-8 编码。
2. 先完成数据来源授权核验。不得把未许可的第三方搜索结果或评论导入。
3. 默认先预览：

~~~bash
python import_restaurants.py data/my_wuhan_restaurants.csv \
  --source-code merchant_claimed
~~~

4. 首次登记来源时，必须填写许可说明并明确确认权利：

~~~bash
python import_restaurants.py data/my_wuhan_restaurants.csv \
  --source-code merchant_claimed \
  --source-name "商家授权提交" \
  --source-type merchant_submission \
  --license-note "商家已确认授权夜寻存储并展示本次提交的门店资料" \
  --approved-by "operator" \
  --rights-confirmed \
  --apply
~~~

5. 已登记来源后，预览通过再加 --apply。导入只会写入待审核队列，不会自动公开。
6. 查看待审核记录：

~~~bash
python review_restaurants.py
~~~

7. 人工核对门店和来源后，才批准公开：

~~~bash
python review_restaurants.py --approve 12,13 --reviewed-by "reviewer" \
  --note "已核对商家官方页面与实际门店地址"
~~~

拒绝记录：

~~~bash
python review_restaurants.py --reject 14 --reviewed-by "reviewer" \
  --note "地址与来源不一致"
~~~

## 公开 API

- GET /api/real-areas：武汉行政区及功能区。
- GET /api/real-catalog/summary：13 个行政区已核验真实门店数量。
- GET /api/real-restaurants：只返回已核验且来源许可有效的真实餐厅。
- GET /api/real-restaurants/{id}：真实餐厅详情、已核验营业时间和菜品。

现阶段 AI 推荐仍使用单独的演示商户数据；在真实餐厅覆盖、字段完整度和更新机制达到要求之前，不将未知的价格、评分、等位或营业状态混入 AI 排序。

 
## 最近两个自然年的资料限定

这是一条硬性校验规则。每条真实门店的 source_updated_at 必须是来源实际更新或采集日期（YYYY-MM-DD），不得留空、填写未来日期或使用超过两个自然年的旧资料。**重新导入旧资料不能冒充更新。**

例如 2026-11-02 的允许范围为 2024-11-02 至 2026-11-02（均包含）。公开时同时检查来源许可、资料日期、人工核验日期和审核状态；任何一项失效，记录自动从真实餐厅列表、地图及图片接口中隐藏。

营业时间和菜品也需要有自己的来源更新日期，未注明来源日期的内容不公开。没有有效坐标时，门店可在列表展示但不会在地图猜测点位。

## 店面照片的授权、拍摄日期与审核

照片必须由门店或其他权利人合法授权，实际拍摄日期也必须在两年内，记录来源凭证、拍摄日期、图片权利人和展示许可。**不允许直接从搜索结果、点评网站或地图图片抓取未经授权的图片。**

照片导入为操作员本地流程，允许去除元数据的 JPG、PNG、WebP，最大 5 MB。导入前请从照片中移除 EXIF、XMP、文字元数据。

~~~bash
python3 manage_photos.py add --restaurant-id 1 --file ./storefront.jpg \
  --taken-at 2026-10-20 --source-url merchant-submission:photo-1 \
  --copyright-holder "门店经营者" \
  --license-note "已获得夜寻保存和展示该照片的授权" \
  --operator editor --rights-confirmed
python3 manage_photos.py list
python3 manage_photos.py approve --photo-id 1 --reviewed-by editor
~~~

未经人工批准的图片不会公开。批准后的图片在门店卡片和详情中出现，并注明拍摄日期和权利人。许可暂停、图片过期或门店资料过期后不再公开。照片原文件保存在本地 data/restaurant_photos 目录，并由 Git 忽略；没有公开游客上传入口。

## 精进后的地图

真实餐厅界面新增「列表 / 地图」切换、按搜索与行政区同步更新的真实门店标记、点击标记查看门店资料，以及无坐标/无数据的明确提示。地图只展示经过核验的坐标，不包含虚构商家点位。

地图前端使用 Leaflet 和 OpenStreetMap 社区瓦片，仅供低流量本地开发测试。公开部署和大量访问前须评估并更换具备服务授权和可用性保障的瓦片供应商。必须保留署名，且不得预下载或批量抓取地图瓦片。

- Leaflet：https://leafletjs.com/examples/quick-start/
- OSM 官方瓦片政策：https://operations.osmfoundation.org/policies/tiles/

当前尚未引入任何未经许可的武汉真实餐厅名单；首次打开真实目录可能为空。旧聊天 AI 推荐仍使用明确标注的演示资料，不能将其误称为真实商户或实时结果。
